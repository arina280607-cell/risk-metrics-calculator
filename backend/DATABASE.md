# База данных

PostgreSQL 17. Таблицы и поля соответствуют схеме `bd.mmd` в корне проекта.
Команды создания таблиц находятся в `backend/schema.sql`.

## Запуск

Установить и запустить Docker с Docker Compose.
Из корня проекта, где находится `compose.yaml`, выполнить:

```sh
docker compose up -d --wait db
```

При первом запуске создаётся БД `risk_metrics` и четыре пустые таблицы:

- `instruments` — справочник облигаций;
- `snapshot_batches` — наборы данных за торговый день;
- `fx_rates` — курсы валют к рублю;
- `instrument_parameters` — параметры облигаций в наборе данных.

Данные сохраняются в Docker volume `postgres_data` между остановками.

## Подключение

Настройки по умолчанию для локальной разработки:

| Настройка | Значение |
| --- | --- |
| Хост | `localhost` |
| Порт | `5432` |
| База | `risk_metrics` |
| Пользователь | `risk_user` |
| Пароль | `risk_password` |

Чтобы изменить настройки, скопировать `.env.example` из корня проекта
в `.env` рядом с `compose.yaml` и отредактировать значения.
Если порт 5432 занят, можно указать, например, `POSTGRES_PORT=5433`.
Пользователь, пароль и имя БД применяются при первом создании хранилища.

Открыть SQL-консоль внутри контейнера:

```sh
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

В SQL-консоли команда `\dt` показывает таблицы,
а `\d instrument_parameters` — поля и связи таблицы параметров.
Для выхода — `\q`.

## Связи

Одна торговая дата соответствует одному набору данных.
Внутри набора для валюты хранится один курс, для облигации — один набор параметров.
Пара `(snapshot_id, currency)` в параметрах ссылается на курс из того же набора.
Для рубля в `fx_rates` нужно записать `RUB` с курсом `1`.

Набор загружается со статусом `LOADING`. После проверки данных загрузчик
должен установить `PUBLISHED` и заполнить `published_at`.
Для облигаций с плавающим купоном `modified_duration` и `convexity`
могут оставаться пустыми: они определяются при расчёте.

## Остановка

```sh
docker compose down
```

Команда сохраняет данные. При повторном запуске таблицы уже существуют.
SQL-файл выполняется автоматически только при первом создании хранилища;
изменения этого файла сами по себе существующие таблицы не обновляют.

На этом этапе backend ещё использует прежнюю SQLite.
Подключение расчётов к PostgreSQL и загрузка данных выполняются отдельно.
